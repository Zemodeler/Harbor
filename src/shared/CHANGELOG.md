# Contract changelog (src/shared/api.ts)

Only optional fields and new methods may be added after the initial contract. Newest first.

- 0.1.16 — Rollback preview (read-only half of task-scoped rollback). Optional `IntegrationSource.merge?: string`: the merge commit Harbor created for that source on the integration branch (set right after a successful merge; absent when the source was already included, except that a re-run keeps the merge an earlier run made for the same pinned commit). New `previewRollback(agentId, target?)` returning `RollbackPreview` (`{ agentId?, target?, targetHead?, supported?, merges?: RollbackMerge[], files?: GitFileChange[], laterCommits?: RollbackLaterCommit[], dependents?: RollbackDependent[], clean?: boolean|null, conflicts?: string[], blockers?: string[], notes?: string[] }`, every field optional). `target` = a local branch, default the checked-out one (a detached HEAD or missing branch gives a blocker). A task is reversed only through the merge commits that brought it onto the target: those recorded in `IntegrationSource.merge`, plus older or hand-made merges whose second parent builds on the task's base and is one of its recorded heads or in its branch; for an integrator, the merges of all its sources. Work that arrived without a merge commit (fast-forward, squash, cherry-pick) is `supported: false` with an explanation. `files` = what the reverts change; `laterCommits` = commits on the target after the task's merge touching those files (`agentId`/`agentTitle` when a Harbor helper made them); `dependents` (`{ agentId, title?, state?, reason: 'dependsOn'|'spec'|'help'|'overlap' }`); `clean` = all reverts simulated newest first with `git merge-tree` apply cleanly (`false` with `conflicts` at the first conflicting one, `null` when it could not be simulated); `blockers` = the task or a dependent is queued/working/waiting, an integration for the target is running, no merge on the target, not a git repository, no base commit. `notes` always says external effects (deploys, sent messages, pushes) are not undone. The preview changes no ref, index or working tree (it may write unreferenced git objects). Rejects for the lead agent and unknown agents. New types `RollbackPreview`, `RollbackMerge`, `RollbackLaterCommit`, `RollbackDependent`.
- 0.1.15 — Branch integration. Optional `Agent.integration?: Integration` (`{ target?, base?, branch?, head?, sources: IntegrationSource[], conflicts?, applied? }`; `IntegrationSource` = `{ agentId, branch?, commit?, state: 'pending'|'merged'|'conflict' }`) marks an integrator: a helper with `role: 'other'` (no new role) that Harbor runs itself, with no CLI (`cli: 'harbor'`, `model: 'git'`). It gates every source before any git write (an approving reviewer whose `testedCommit` is the branch's current head and is not outdated, no reviewer asking for changes on it, an existing `harbor/*` branch), pins each source head and merges SHAs with `--no-ff` into a new `harbor/integrate-<target>-<id6>` worktree from `base` (the target's head at start), in dependency then creation order, skipping sources already contained (a re-run is idempotent). A conflict is recorded in `conflicts`, the merge is aborted and the run stops (earlier sources stay merged, later ones `pending`). Then the project's `.harbor/checks.json` runs on `head` (`Agent.checks`/`testedCommit`). State `done` only when everything merged and the checks pass; otherwise `failed` with `summary` starting `Refused:`, `Merge conflict:` or `Checks failed on integration:`. A message to the integrator's conversation, or `resumeAgentSession` when stopped, runs it again. The lead creates one with `HARBOR_DELEGATE: {"role":"integrator","sources":[refs or ids],"target"?}`. New `integrateBranches(projectId, agentIds, target?)` (user-started; returns the queued integrator, which waits for the sources and their reviewers; not reported to the lead), `applyIntegration(agentId)` (fast-forwards `target` to `head` only; rejects unless the integration is done with everything merged, the project folder has no uncommitted tracked changes, and the target is still at `base`; idempotent once applied; never pushes or forces) and `getChanges(agentId)` (committed `GitFileChange[]` of a helper branch since its base, or of an integration `base..head`; `[]` without a branch). New types `Integration`, `IntegrationSource`.
- 0.1.14 — Helper results and Harbor-run checks. Optional `Agent.result?: AgentResult` (`{ outcome: 'done'|'partial'|'blocked', summary, verdict?: 'approve'|'changes', checks: {cmd, ok}[], commit? }`): the helper's own `HARBOR_RESULT` line, replaced on every run (absent when the run printed none). `verdict` comes from reviewers; `commit` is what the run examined (a reviewer's `testedCommit`, an edit helper's branch head). Its `checks` are claims. Optional `Agent.checks?: CheckOutcome[]` (`{ cmd, ok, exitCode, timedOut?, durationMs }`): commands from the project's `.harbor/checks.json` that Harbor itself ran in an edit helper's worktree after its run (evidence). They ran on `Agent.testedCommit`, and `Agent.outdated` turns true once that branch moves. Without a checks file nothing runs and edit helpers get neither `checks` nor `testedCommit`. A reviewer's approval covers the branch's current head only when `result.verdict === 'approve'` and `outdated` is false. A reviewer's follow-up re-pins `testedCommit` to the head it then examines. New types `AgentResult`, `CheckOutcome`. No new methods.
- 0.1.12 — Routing settings, all optional on `Settings` (absent = the previous behaviour): `concurrencyLimit` (helpers running at once per project, 1–8; default 4), `allowedModels` (per CLI, the catalog models automatic routing may pick; absent or empty = all), `rolePreferences` (per helper role a preferred `cli` and optional `model`: a score bonus that never overrides hard limits), `effortPolicy` (`adaptive`|`conserve`|`quality`), `lowAllowancePolicy` (`reduceEffort`|`switch`), `subscriptionReserve` (0–50: percent of allowance kept free; a model at or above `100 - reserve`% used is skipped) and `projectOverrides` (map by project id of `ProjectSettings`, the same fields; a project value wins per field, per CLI and per role). New types `EffortPolicy`, `LowAllowancePolicy`, `RolePreference`, `ProjectSettings`. `setSettings` rejects unknown enum values and malformed shapes, clamps and rounds numbers, drops unknown roles and blank model names; a key set to `undefined` resets that field, and `projectOverrides: { [id]: {} }` (or `undefined` for that id) removes the project's overrides. Each project entry replaces that project's previous overrides. No new methods.
- 0.1.13 — Image attachments, conversation modes, session complexity. `send(conversationId, text, attachments?)` takes optional images (`{ name, mime, dataBase64 }`; png/jpeg/gif/webp, max 10 MB each, 6 per message); `Message.attachments?: Attachment[]` (`{ name, mime, path? }`) holds them. New `ConversationMode` (`default|auto|plan|goal`), optional `Conversation.mode` / `Conversation.goal`, and new `setConversationMode(conversationId, mode, goal?)` (goal mode requires a goal; returns the updated conversation, also emitted as a `conversation` event). Optional `SessionActivity.complexity` and `SessionActivity.effort` show how the lead turn was routed.
- 0.1.11 — Optional `Agent.testedCommit` (the exact commit a reviewer examined, taken when its run starts) and `Agent.outdated` (computed: the reviewed branch's head moved since `testedCommit`, so the verification no longer covers it).
- 0.1.10 — New `resumeAgentSession(agentId)`: continues a `stopped` helper in its saved native CLI session (e.g. after a Harbor restart). It tells the agent to inspect its worktree first and never repeat completed steps. Rejects for the lead agent, for agents that are not stopped, and for agents without a saved session. Show it as a "Resume" action on stopped agents. (Distinct from `resumeAgent`, which only un-pauses queued work.)
- 0.1.9 — Queue controls: new `setAgentPriority(agentId, priority)`, `pauseAgent(agentId)` and `resumeAgent(agentId)`, and optional `Agent.priority` (higher starts first; absent = 0) and `Agent.paused` (a paused queued agent does not start, and stays `queued`). Pausing never interrupts a running agent. Cancelling a queued assignment is the existing `stopAgent`. The lead agent (`role: 'main'`) has no queue position: these methods reject it.
- 0.1.8 — Read-only Git view: new `getGitOverview` (branches with ahead/behind against the detected base branch, worktrees with uncommitted counts, and the Harbor helper that owns each `harbor/*` branch), `getGitLog` (commits with parents and refs for a graph), `getGitChanges` and `getGitDiff` for a `GitTarget` (`{}` = uncommitted project folder, `{ branch }` = since its merge-base with base including a helper worktree's uncommitted work, `{ commit }` = that commit against its first parent). New types `GitBranch`, `GitWorktree`, `GitOverview`, `GitCommit`, `GitFileChange`, `GitTarget`. Only branches and commits that exist in the repository are accepted; credential files are listed with `hidden: true` and their diff is never returned.
- 0.1.7 — Optional `UsageWindow.model` (a per-model limit such as Fable or Opus; absent = account-wide) and `UsageWindow.projectedPct` (where usage lands at reset at the current pace).
- 0.1.6 — Optional conversation pin/archive/custom-title fields and persisted per-conversation `activity` (state, timing, connection, model, and current step), plus optional `reviewBase`; `conversation` events update session status independently of the shared main agent. New `updateConversation`, `searchConversations`, `stopConversation`, `getReview`, and `openProjectFolder` methods. Review snapshots are read-only current diffs, with no inferred verification claims. Optional `Settings.desktopNotifications` enables native background completion/attention notifications.

- 0.1.5 — `HarborEvent` variant `question` (`requestId`, `conversationId`, `prompt`, `options?`, `allowText?`, `agentId?`) and `answerQuestion(requestId, answer)` (new method). An agent that needs a user decision ends its turn with a question; show it as a pop-up and send the chosen option or typed text with `answerQuestion`, which delivers it as the user's next message in that conversation. Renderers must ignore unknown event types.
- 0.1.4 — `Project.image?` (a small `data:image/...` URL) and `setProjectImage(id, image|null)` (new method; `null` clears it). The image is stored with the project and survives restarts.
- 0.1.3 — `Agent.conversationId?` (optional): the main-agent conversation that created a subagent. All conversations of a project share one main agent, so `parentId` alone cannot tell which chat a subagent belongs to.
- 0.1.2 — `deleteConversation(id)` (new method; removes the conversation and its messages only). `UsageWindow.period?` (`session`|`weekly`) and `UsageWindow.source?` (`reported` = read from the provider/CLI, `estimated` = Harbor-run count). Weekly windows now appear next to the 5h one.
- 0.1.1 — `CliStatus.authState?` (optional): `signedIn`, `signedOut`, or `unknown`. `signedIn` stays false when unknown, so show "status unknown" (not "login required") when authState is `unknown` and installed.
- 0.1.0 — initial contract, identical to the spec.
