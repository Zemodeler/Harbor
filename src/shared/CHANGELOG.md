# Contract changelog (src/shared/api.ts)

Only optional fields and new methods may be added after the initial contract. Newest first.

- 0.1.47 — Project lifecycle and publish (all optional, desktop only: every new method is remote scope `never`). New optional `Settings.projectsDir?` (where new projects go; default `Documents\Harbor Projects`). New methods: `createProject?(draft: NewProjectDraft)` (name, optional parent folder, template `empty`|`node-ts`|`python`|`static-web`, optional GitHub repo through the user's own `gh`, optional first prompt; makes the folder and template files, `git init`, first commit, registers the project; returns `CreateProjectResult` with `warnings` for anything skipped; on failure removes only what the call created), `previewDeleteProject?(id)` (read-only `DeletePreview`: running agents, worktrees, `harbor/*` branches with unmerged/unpushed counts, folder state, blockers) and `deleteProject?(id, scope, confirmName?)` with `DeleteScope` `forget` (same as `removeProject`) | `worktrees` (also Harbor's worktrees and `harbor/*` branches) | `folder` (also the project folder; needs the project name typed; never touches the GitHub remote), `previewPush?(projectId, branch)` (`PushPreview`: commits to push, ahead/behind, secret scan of exactly those commits: type, file and line only, with a `fingerprint` of the findings), `pushBranch?(projectId, branch, opts?)` (plain `git push`, never forced; the default branch needs `allowDefaultBranch`; secret findings the allowlist does not cover block it unless `secretOverride` carries the preview's fingerprint), `createPullRequest?(projectId, draft)` (pushes if needed, then `gh pr create`), `setRemote?(projectId, url, opts?)` (https/ssh URLs only; changing an existing `origin` needs `replace`) `getGithubStatus?()` and `browseFolder?()` (folder picker for the Projects folder setting; null when cancelled). `removeProject` is unchanged. Harbor never reads or stores credentials: git and `gh` use their own credential helpers.
- 0.1.45 — `stopAgent(agentId, conversationId?)` gains an optional second argument, used when `agentId` is the lead: the conversation the user is looking at. Its running lead turn (if any) and its helpers stop; other conversations of the project are untouched. Without it, as before, the project's running lead turns and their helpers stop; but when no lead turn is running, nothing happens any more (stopping an idle lead used to stop every helper of the project, including other conversations' running implementers). Helpers are unaffected by the argument. Renderers pass the open conversation.
- 0.1.44 — New optional method `renameProject?(id, name): Promise<Project>`: trims the name (1 to 120 characters) and returns the updated project; the folder on disk is not renamed.
- 0.1.43 — No type change. `send(conversationId, text, attachments?)` now accepts any file, not only images: `{ name, mime, dataBase64 }` as before. PNG, JPEG, GIF and WebP are still validated and stored as images (10 MB, 6 per message). Every other file is stored unchanged under its own name (`<id>-<name>`, 50 MB, 10 files per message in total), returned as an `Attachment` with `mime: 'application/octet-stream'`, a `path` and no `url`. The agent is told the path in the prompt and its folder is made readable. A file turn skips the concierge and goes straight to a lead.
- 0.1.42 — Optional `Agent.stopKind?: 'user'|'cap'|'restart'|'loop'|'spend'`, sent only while the agent is `stopped`: who stopped it (the user, Harbor's time limit, a Harbor restart, the loop guard, or a spend ceiling from 0.1.38). Absent = unknown (records from before the field, or not stopped). Renderers that ignore it keep reading the error text in `summary`.
- 0.1.41 — Remote API (all optional). New types `RemoteScope` (`'read-only'|'answer-permissions'|'full'`), `RemoteTokenInfo` (`{ id, name, scope, created, lastUsed? }`) and `RemoteSettings`, and optional `Settings.remote?: RemoteSettings` (`enabled`, `host` default `127.0.0.1`, `port` default 47821, `allowFullScope`, `allowPlainHttp`, `tlsCertFile`/`tlsKeyFile`, `allowedHosts`; validated by `setSettings`, read once at startup). New optional methods `createRemoteToken?(name, scope)` → `{ token, info }` (the token is returned only here; only its SHA-256 is stored; `full` is refused unless `remote.allowFullScope` is true), `listRemoteTokens?()` (never includes the token) and `revokeRemoteToken?(id)` (unknown id = no-op; open event streams of that token are closed). The main process now also rejects `answerPermission` calls whose `requestId` is not a short string, whose `allow` is not a boolean, or whose options are not an object. Behaviour without contract change: with `remote.enabled` the app (and always `npm run headless`) serves `POST /v1/invoke/<method>` (`{ args: [...] }` → `{ result }` or `{ error }`), `GET /v1/whoami` and a WebSocket event stream at `/v1/events` (each frame one `HarborEvent` as JSON), all with `Authorization: Bearer <token>`. Every method is classified by scope: read-only = list/get methods and events; answer-permissions adds `answerPermission` and `answerQuestion`; full adds the methods that start, stop or change work. `openLogin`, `addProject`, `openProjectFolder`, `openWorkspace`, `exportDiagnostics` and the three token methods are never callable remotely; a free reset is never answerable remotely; "always allow" needs full scope; `setSettings` cannot change `remote` remotely. Requests carrying an `Origin` header or a Host other than loopback/the bind address/`allowedHosts` are refused, and no CORS headers are sent. Only one Harbor (app or headless) may use a data folder at a time (`harbor.lock`).
- 0.1.40 — Project knowledge and repo map (all optional). New type `ProjectNote` (`{ id, text, topic?, created, updated?, author: 'lead', conversationId? }`) and `ProjectNoteTopic` (`convention`|`pitfall`|`howto`|`other`). New optional methods `listProjectNotes?(projectId)` (oldest first) and `removeProjectNote?(projectId, noteId)` (returns the remaining notes; an unknown note id is a no-op; both reject an unknown project). Notes are written by the lead with a new protocol line `HARBOR_NOTE: {"text","topic"}` (per-turn tag like every protocol line, at most 3 per turn, 400 characters each, secret-looking strings masked, a restated note refreshes the existing one instead of adding a copy, at most 40 per project with the least recently confirmed dropped). They are model-written and advisory: prompts present them as information, never instructions, and say the user's message, AGENTS.md and the repository win. Behaviour changes that need no contract change: lead turns carry the relevant notes the session has not seen yet (about 400 tokens at most; all of them again when the native session is lost); helpers start with the relevant notes (about 300 tokens at most) and, except reviewers, a repository map (file tree, entry points, package scripts, header-comment summaries, README summary, a test command guess; at most 6,000 characters, about 1,500 tokens; credential files are never listed or opened), cached per project by HEAD and working-tree status. The concierge gets neither.
- 0.1.39 — Measurement (all optional). New optional methods: `getTaskReport?(conversationId)` returns a `TaskReport` built from Harbor's own usage records (kept 8 days; older runs are missing and a note says so): `totals` (runs, failed and partial runs, runs without token counts, input/output/cache tokens, `billableKTok`, `agentMinutes` = summed run time, `wallMinutes` = first run start to last run end, `costUsd` only when a CLI reported one, and `quota`), per agent (`agents`, including helpers that never ran, with the CLI/models each used), per CLI/model (`byModel`, with the roles it served), every run (`runs`) and the routing decisions recorded on messages (`decisions`). A lead conversation covers the lead's turns in that conversation (the concierge's first pass included) and every helper reporting to it; a helper's own conversation covers that helper. Every `quota` entry (`QuotaEstimate` = `{ pool, period, pct }`) is Harbor's ESTIMATE from billable tokens, the catalog's cost per token and the calibrated quota per token, never the provider's figure; a run without token counts has `noTokens: true` and no quota (unknown, not zero). `rateResult?(targetId, rating, note?)` stores a `ResultRating` (`up` | `down` | `redo-stronger`, optional note up to 1000 characters) about an agent (its last CLI/model) or a message that carries routing details; rating the same target again replaces the earlier rating; integrators, rollbacks and plain messages are refused. Ratings are local evidence kept in state.json (newest 5000) and never edit capabilities.json. `listRatings?(opts?)` (newest first, optional `projectId`) and `getRatingSummary?(opts?)` (`by` `cli` | `model` (default) | `need`; a rating counts once per need of the rated work, `unspecified` without needs) return `RatingSummaryRow`s with `approval` = up / total. `replayRouting?(opts?)` (read-only) re-routes recorded decisions (newest `limit`, default 200, max 2000; one conversation with its helpers, one project, or all) under the current catalog and settings (`baseline`) and under a what-if (`alternative`: `catalog` = capabilities.json-style entries validated like the file, `settings` = a patch validated like `setSettings` and applied to a copy), both judged under the same assumed state (every pool neutral, no load, no failure history; stated in `assumption`), and reports per decision whether the choice changed, `priceDelta` (router price, an estimate) and `costPctDelta` (expected weekly-quota % of the binding pool, an estimate), plus a summary with the moves. New optional `Message.details.request?: RoutingRequestRecord` (role, difficulty, size, needs, required, tier, fixed effort, interactive, urgency, retry, named CLI, session CLI) on every new routing decision; older decisions are replayed from the agent record and marked `approximate`. New types `RoutingRequestRecord`, `QuotaEstimate`, `TaskReport`, `TaskReportTokens`, `TaskReportRun`, `TaskReportAgent`, `TaskReportModel`, `TaskReportDecision`, `ResultRatingValue`, `ResultRating`, `RatingSummaryRow`, `RoutingReplayOptions`, `RoutingReplayChoice`, `RoutingReplayDecision`, `RoutingReplay`. No existing member changed.
- 0.1.38 — Spend ceilings and secret scanning (all optional). New optional `Settings.spendCeilings?: SpendCeilings` (`{ task?, day?, week? }`, each a `SpendLimit` `{ kTokens?, minutes? }`) and `Settings.secretAllowlist?: string[]`; both are also `ProjectSettings` fields (`projectOverrides`). Spend is an ESTIMATE from Harbor's own runs only (billable k-tokens as the budget governor counts them, and agent-minutes = run durations summed), never the provider's quota. `task` = one user request in a conversation (the concierge, every lead turn and the helpers it started); `day`/`week` = rolling 24 hours / 7 days; a global value counts every project, a project's own value counts that project (both apply; a project's `task` value replaces the global one). `setSettings` rejects non-numbers and values at or below 0, rounds and clamps (k-tokens 1..1e8, minutes 1..1e6), drops empty limits; `secretAllowlist` must be a list of single-line patterns (at most 200; path globs or `type@glob`). New types `SpendLimit`, `SpendCeilings`, `SpendScope`, `SpendStatusEntry`, `SpendStatus`. New optional method `getSpendStatus?(projectId?, conversationId?)`: the configured ceilings with spent amount, threshold (limit times 1 + the extensions the user allowed), `hit` and `extensions`; always `estimate: true`. Behaviour changes that need no contract change: before every run (concierge, lead, helper) a reached ceiling raises a `permission` event of kind `tool` with `tool: 'Harbor spend ceiling'` and `alwaysAllow: false`; yes allows one more limit's worth (a day/week extension lasts one window) and is persisted; no, or no answer before `expiresAt`, keeps the run from starting (the lead posts "The lead did not start: ..."; a denial holds until the user's next message). Runs in flight are measured every 30 s and on every usage report; a reached ceiling stops every run in its scope (work kept; system message "Spend ceiling reached: ..."), a helper stopped so ends `stopped` with error "Harbor stopped this run: Spend ceiling reached: ..." and wakes the lead (whose turn asks first). Counters survive restarts (usage events, extensions, and the last live measurement of runs a crash interrupted). Secret scanning: Harbor scans what an edit helper's run committed (added lines and added credential-named files such as `.env`, keys, keystores) and reports type, file and line only (never the value) in the helper's report and the evidence reviewers and the lead read; an integration scans `base..head` after merging and fails with summary `Secret scan: ...` unless nothing is found, the project's `secretAllowlist` (or a `harbor:allow-secret` marker on the line) covers it, or the user says yes to a `permission` event with `tool: 'Harbor secret scan'` (remembered for exactly those findings on that head). `applyIntegration` refuses an integration whose head is not cleared (an integration from before this version is scanned then).
- 0.1.37 — `HarborEvent` `question` gains optional `multiSelect?` (several options may be picked) and `questions?` (follow-up questions of the same card: `prompt`, `options?`, `allowText?`, `multiSelect?`). The renderer answers all of them with one `answerQuestion` text. Renderers that do not know the fields still work: they show the first question.
- 0.1.36 — MCP servers (all optional). New types `McpTransport` (`stdio`|`http`|`sse`), `McpServerDraft` (`name` = 1-64 letters, digits, `-`, `_`; `transport`; stdio: `command` = a bare program name or an absolute path, `args`, `env`; http/sse: `url`, `headers`; `allowUnattended` = its tools may run without asking), `McpServer` (adds `enabled` for the project asked about, `defaultEnabled`, `updated`), `McpTestResult` and `CliMcpServer`. New optional methods `listMcpServers?(projectId?)`, `saveMcpServer?(server, { previousName?, projectId? })` (adds, or replaces `previousName`; a rename keeps the project choices; problems are listed without ever repeating a value), `removeMcpServer?(name, { projectId? })`, `setMcpServerEnabled?(name, enabled | null, projectId?)` (as for skills: with a project its choice, without one the global default, `null` = back to the default; servers start off everywhere), `testMcpServer?(server, { confirmCommand? })` (stdio: `confirmCommand` must repeat the command, the user's explicit OK to run it; started as one argv, never a shell string, in a fresh temp folder with the custom-CLI environment allowlist plus its own env, killed after `initialize` + `tools/list` or 20 s; http/sse: the same requests to the URL with its headers; entered env and header values are masked in what comes back) and `listCliMcpServers?(projectId?)` (servers in Claude Code's `~/.claude.json` user and local scopes and `<project>/.mcp.json`, and Codex's `config.toml`, read-only: names and kinds only). New optional `Settings.claudeOwnMcp` (boolean; default off). New optional `CustomCliDescriptor.run.mcp?: { args }` with the placeholder `{mcpConfigFile}` and the whole-argument slot `{mcpArgs}` (appended at the end when absent); a custom CLI with it reports `features.mcp`. Behaviour that needs no further contract change: the registry is stored in the data folder's `mcp-servers.json` as plain text (owner decision); its values are never put in a bundle (bundles use an allowlist), in diagnostics, in logs or in run details. For each lead and helper run (never the concierge) Harbor gives the project's enabled servers to the chosen CLI: Claude Code through a per-run `--mcp-config <file>` in its own folder under the OS temp folder (deleted when the run ends, also on failure or abort), Codex through `-c mcp_servers.<name>.command|args|env|url|http_headers=<TOML literal>` overrides (SSE servers and values with a quote, `%` or a line break are skipped for Codex), custom CLIs through `run.mcp` (the same JSON file as Claude). A server reaches a run only when each of its tool calls can be asked about (Claude edit runs, through the existing tool permission channel: tool names `mcp__<server>__<tool>`, "always allow" rules work as for other tools) or the user allowed it without asking (`allowUnattended`; Claude then gets `--allowedTools mcp__<server>`); Codex, custom CLIs and Claude in auto mode get only those. Read-only runs (planners, reviewers, plan mode) get no MCP servers. Claude runs add `--strict-mcp-config` unless `Settings.claudeOwnMcp` is on, and always in auto mode, so Claude Code's own MCP configuration stays out of Harbor runs by default (it was inherited before this version). A CLI without MCP support gets nothing. What a run got or did not get, and why, is added to its run details by server name.

An imported conversation is read-only history of the project's lead: `send`, `setConversationMode` (and the orchestrator itself) refuse it; its first message is a system line saying where it came from and that agents see it only as quoted history. New types `ChatImportSourceId`, `ImportedInfo`, `ChatImportSourceInfo`, `ChatImportEntry`, `ChatImportPreview`, `ChatImportResult`, `BundleSelection`, `BundleItem`, `SecretFinding`, `BundleExportPreview`, `BundleExportResult`, `BundlePreview`, `BundleImportOptions`, `BundleImportResult`. New optional methods: `previewBundleExport?(projectId, selection)` builds a `.harbor.zip` (bundle version 1) in memory from an allowlist (routing preferences = the project's `projectOverrides` entry, a `.harbor/checks.json` reference, tool rules, the project's skill choices for repository skills and for skills carried in the bundle, the chosen lead conversations with user/assistant/system messages and their decisions, image files only with `images`, the chosen skills' files) and returns exactly what goes in, what never does (credentials, MCP/env secret values, CLI paths and custom CLI descriptors, run logs and helper reports, session ids) and the secret scan's findings (masked); machine paths in text are rewritten (project folder to project-relative paths, worktrees to worktree-relative, the data folder to `<harbor-data>`, home to `~`, any other absolute path to a placeholder); `exportBundle?(token, { keepSecrets?, redactSecrets? })` opens a save dialog and writes that preview (with findings, one of the two options is required; `redactSecrets` replaces them with `[redacted]`), `null` when cancelled; `browseImportFile?('bundle' | 'chatExport')`; `previewBundle?(path)` reads and checks a bundle with the skill-import archive safeguards (zip-slip, absolute and device names, links, encryption, ZIP64, entry and size caps; every inner path must match the bundle layout, so none is used on disk) and writes nothing; a bundle of a newer version is refused with a message to update Harbor; `importBundle?(token, { projectId, settings?, replaceSettings?, toolRules?, skillChoices?, skills?, conversations? })` brings the chosen parts into an existing project with new ids: routing preferences only with `replaceSettings` when the project has its own (refused before anything is written otherwise), tool rules only when Harbor would accept them as "always allow" rules (never-always commands are skipped), skills through the library's import checks (taken names keep both), skill choices never replacing the project's own, conversations as read-only imported history; the checks file is never approved by an import. `listImportSources?()` (reads no transcript), `previewImport?(source, { path? })` (Claude Code and Codex: lists the session files with dates and sizes without reading them, plus Codex thread names from its session index; account exports: reads the picked `conversations.json` or export `.zip`), `importConversation?(projectId, token, entryIds)` (reads only the chosen entries; parsers tolerate unknown fields, cut-off, oversized, deeply nested and badly encoded input and report what they skipped: tool calls and results, thinking, injected context, unreadable lines) and `continueImported?(conversationId, { cli })`: a new conversation (`continuedFrom` set) whose first lead turn skips the front desk and gets Harbor's handoff of the imported chat (`handoff.ts`: the first request, the latest exchange and its decisions, every line quoted and introduced as data written outside Harbor), with routing preferring that CLI; another tool's native session is never resumed. The claude.ai and ChatGPT parsers follow the documented export shapes and are not verified against real exports.
- 0.1.34 — Document viewer (all optional). New types `DocumentKind` (`markdown`|`text`|`code`|`json`|`csv`|`image`|`svg`|`html`|`pdf`|`office`|`binary`|`tooLarge`), `DocumentView` (`path` = real absolute path, `name`, `kind`, `size`, `modified`, `root` = `project`|`worktree`|`attachments`|`skills`|`picked`, optional `agentId`, `relPath`, `language`, `text`, `html`, `dataUrl`, `mime`, `unchanged`, `canOpenExternally`, `note`), `DocumentRefusalReason` (`invalid`|`outside`|`link`|`notFound`|`notFile`|`credential`|`unavailable`) and `DocumentResult` (`{ ok: true, document }` or `{ ok: false, reason, message }`; a refusal never repeats an outside path). New optional methods `openDocument?(projectId, path, { agentId?, since? })` (relative paths resolve against that agent's worktree, else the project; the file must resolve, after links and junctions, inside the project, one of its helpers' worktrees, the attachments folder of one of its conversations, Harbor's skills library, or a file picked with `pickDocument` this session; a symlink as the file itself and credential files are refused; `since` = the `modified` already shown, an unchanged file comes back with `unchanged` and no content), `pickDocument?(projectId)` (native file dialog; that exact file, never its folder, is allowed for the rest of the session; null when cancelled) and `documentAction?(projectId, path, 'openExternal'|'reveal', { agentId? })` (same path checks; `openExternal` only for documents and images, never programs, scripts, HTML or SVG; `reveal` selects the file in Explorer). New preload-only `pathForFile?(file)` (Electron `webUtils.getPathForFile`, for dropped files; not an IPC method, excluded from `InvokeMethod`). New event `{ type: 'document', projectId, conversationId, path, title?, agentId? }`: an agent's `HARBOR_OPEN_DOCUMENT: {"path","title"?}` line (lead and helpers, up to 3 per turn; garbage JSON, a missing or multi-line path is reported as an ignored protocol line) passed the path checks; the chat also gets a line naming the file, and a refused one gets a note (the journal records the reason only, never the path). Content rules: text up to 5 MB (UTF-8, or UTF-16 with a BOM; NUL bytes or invalid UTF-8 = `binary`), images (PNG/JPEG/GIF/WebP, bytes checked) and SVG up to 10 MB / 5 MB as `data:` URLs (SVG only ever shown as an image), HTML as `text` plus a sanitised `html` for an iframe with an empty `sandbox` (scripts, frames, plugins, forms, media, `<base>`/`<link>`/`<meta>`, event handlers, remote and script URLs, CSS `url()`/`@import` removed; a `default-src 'none'` CSP meta first). PDF and Office files carry no content: Electron's PDF viewer cannot run under Harbor's CSP and navigation guard (verified on Electron 44.7), so they offer the default app.
- 0.1.33 — Screenshots and image display (all optional, plus one widened value). The `permission` event's `kind` may now also be `'screenshot'` (renderers that do not know it must ignore it, as for unknown event types; existing kinds are unchanged), with a new optional `screenshot?: ScreenshotRequestInfo` (`target` `screen`|`window`, the agent's `title` hint and `why`, `agentRole`, `agentTitle`, `projectId`, `projectName`, `recent` = that agent had a capture less than a minute ago). New types `ScreenshotRequestInfo` and `ScreenshotSource` (`id`, `name`, `kind`, `thumbnail` = small `data:image/png` taken at that moment, `suggested`). New optional methods `previewScreenshot?(requestId, { sourceId? })` (a live preview: every window and screen with a thumbnail, or one source larger; nothing is stored or sent to a model; call again to refresh) and `answerScreenshot?(requestId, { allow, sourceId?, forConversation? })` (allow needs a `sourceId` that this request's preview returned, so the target is always the user's pick, never the agent's text; `forConversation` = later window requests of the same conversation capture that same window without asking: windows only, rejected for a screen, off unless sent, forgotten on stop and restart). `answerPermission(id, false)` also declines a screenshot; `answerPermission(id, true)` is rejected for one. `listPendingPermissions` includes screenshot requests. New optional `Attachment.url` (`harbor-file://attachments/<conversationId>/<file>`, set on new attachments and filled by `listMessages` for older ones under Harbor's attachments folder) and `Attachment.origin` (`user` | `screenshot` | `agent`). Behaviour that needs no further contract change: agents (lead and helpers) may end a turn with `HARBOR_SCREENSHOT: {"target":"screen"|"window","title"?,"why"}` (one per turn; garbage JSON, an unknown target or no reason is reported as an ignored protocol line). Harbor posts the request in the chat, raises the event (declined after 5 minutes), brings its window forward, and on a yes captures the chosen source in the main process and saves a PNG under `<data>\attachments\<conversationId>\`; the image is shown in the asking agent's conversation and handed to that agent on its next turn, as an image for a CLI whose `features.images` is true (Codex `--image`, Claude reads the file) and otherwise as a file path with a note that the CLI cannot see it. A decline, timeout or failure is told to the agent; a stop withdraws the request and resumes nothing. At most one capture per agent per minute without a fresh yes (a conversation-allowed window is not used within that minute, nor while Harbor's window is hidden or minimised). Every request and capture adds a `screenshot` journal line (kind of source and agent only: never the image, never the window title). New protocol line `HARBOR_SHOW_IMAGE: {"path"}` (up to 3 per turn): a PNG/JPEG/GIF/WebP inside the project folder or the agent's worktree (after links and junctions; magic bytes checked; 10 MB cap) is copied into the conversation's attachments and shown; anything else is refused with a note. The main process serves `harbor-file://` only for files Harbor wrote under its attachments folder (same conversation-id guard, stored-name pattern, real-path check), only to Harbor's own document; the renderer CSP `img-src` allows `harbor-file:`.

- 0.1.32 — Skills (all optional). New types `SkillSource` (`library` = `%APPDATA%\Harbor\skills`, `project` = `<project>\.harbor\skills`, `claude`/`codex` = found read-only in that CLI's own folder: `~\.claude\skills`, `<project>\.claude\skills`, `$CODEX_HOME\skills`), `Skill` (`id` = `<source>:<folder>`, `name`, `description`, `source`, absolute `path`, `readOnly`, `enabled` for the project asked about, `defaultEnabled` = the global default, `files`, `bytes`, `hasScripts`, and for library skills `hash` (sha256 of the files recorded at import), `importedFrom`, `importedAt`; `problems` = why it cannot be used, e.g. no description, a link inside, SKILL.md over 256 KB), `SkillFile`, `SkillDetail` (adds `text` = SKILL.md, `truncated`, `fileList`, `currentHash`, `modified` = library files no longer match the recorded hash), `SkillImportSource` (`folder` | `zip` path, or `github` with `owner/repo[/path]` or a github.com `/tree/<ref>/<path>` address), `SkillImportCandidate`, `SkillImportPreview`. New optional `CustomCliDescriptor.run.readDir?: { args }` (per folder, `{path}`; new whole-argument slot `{readDirArgs}`, appended at the end when absent). New optional methods `listSkills?(projectId?)`, `readSkill?(skillId, projectId?)`, `setSkillEnabled?(skillId, enabled | null, projectId?)` (with a project: that project's choice; without: the global default; `null` returns to the default; defaults: library and project skills on, Claude/Codex skills off), `previewSkillImport?(source, { confirmDownload? })` (folder and zip: reads and checks, writes nothing; GitHub: the first call only resolves one commit and lists names and sizes; a second call with `confirmDownload` = that listing's `token` downloads exactly those files and checks each against its git blob hash), `importSkills?(token, { names? })` (copies the checked files into the library; a taken name gets `-2`, `-3`... so both are kept; records source and hash), `removeSkill?(skillId)` (library only) and `browseSkillSource?('folder' | 'zip')`. Imports refuse path traversal, absolute and drive paths, symbolic links and junctions, encrypted or ZIP64 archives, more than 200 files, more than 5 MB of skills (1 MB per file, 20 MB per archive), and never run anything; a "contains scripts" warning names script files. Behaviour that needs no further contract change: lead and helper runs (never the concierge) get a short skills section in their system prompt (name, description and SKILL.md path per enabled skill; the agent reads a SKILL.md only when its task matches, and skill text is introduced as third-party data that cannot override Harbor's rules); a skill the chosen CLI already loads natively (`CliStatus.features.nativeSkills` and the skill sits in its own folder) is not listed again; a skill outside the run's folder is reachable through `--add-dir` (Claude), `run.readDir` (custom CLIs) or directly (Codex), and a CLI with none of these gets small SKILL.md files (8 KB each, 24 KB in all) inlined and the rest named as unavailable. - 0.1.31 — Custom CLIs (all optional). - 0.1.27 — Budget routing (all optional). New optional method `setConversationDeadline?(conversationId, deadline | null)`: `deadline` is an epoch-ms time the owner needs the conversation's work by (`null` clears it); it returns the updated conversation and emits a `conversation` event. The reason text shows the calculation: difficulty and its signals, the estimated price of the choice against the runner-up, every pool's state, the reserve and the urgency.

- 0.1.18 — Rollback, write half. New `rollbackTask(agentId, target?)` queues a rollback agent and returns it: like an integrator, `role: 'other'` run by Harbor itself (`cli: 'harbor'`, `model: 'git'`), started by the user (not reported to the lead), with its own conversation `rollback: <title>`. It rejects unknown agents, the lead, a rollback agent, a blank target, and a second rollback while one in the project is unfinished. Optional `Agent.rollback?: Rollback` (`{ taskId, target?, base?, branch?, head?, merges: RollbackRevert[], conflicts?, applied? }`; `RollbackRevert` = `{ commit, agentId?, integrationId?, state: 'pending'|'reverted'|'conflict', revert? }`) marks it. A run first re-runs `previewRollback` as a gate: any blocker fails it before any git write, with `summary` `Refused: ...`. Otherwise it pins `base` (the target's head) and the task's merges, creates a new `harbor/rollback-<task>-<id6>` worktree from `base`, and reverts the merges newest first with `git revert -m 1` (each `revert` is the commit made). On a conflict the unmerged paths go to `conflicts`, the revert is aborted and the run fails with `Rollback conflict: ...`; earlier reverts stay on the rollback branch and the target is never touched. Then the project's `.harbor/checks.json` runs on `head` (`Agent.checks`/`testedCommit`). The state is `done` only when every merge is reverted and the checks pass; otherwise `failed` with `Checks failed on rollback: ...`. A message to its conversation, or `resumeAgentSession` when stopped, runs it again on the same branch and base, skipping reverts already made. `applyIntegration(agentId)` now also applies a done rollback, with the same rules (fast-forward only; rejects when not done, the project folder has uncommitted tracked changes, the target moved since `base`, the rollback branch moved, or the target is checked out in another worktree; never pushes or forces). For both kinds, applying again once the target is at `head` is a no-op. After a rollback is applied, `outdated` turns true on the reverted task, the helpers and integrators of its merges, its dependents and their reviewers (those with a `testedCommit`). New types `Rollback`, `RollbackRevert`.
- 0.1.17 — Rollback preview (read-only half of task-scoped rollback). - 0.1.15 — Branch integration.
