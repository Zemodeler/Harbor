# Contract changelog (src/shared/api.ts)

Only optional fields and new methods may be added after the initial contract. Newest first.

- 0.1.31 — Custom CLIs (all optional). New type `CustomCliDescriptor`: a CLI described as data (id, name, approved `exe`, optional `version`/`status`/`login` commands, `run` with argument templates, prompt on stdin or a temp file, extra `env`, `text` or `jsonl` output with a JSON-path `map`, optional `resume`, `effort`, `permissions` and `image` arguments, `models` for the catalog, `acceptReadOnlyRisk`, and Harbor-set `approvedHash`/`approvedAt`). New types `CliArg`, `CliTemplate`, `CliDryRun`, `CliDryRunStep`, `CliFeatures`. New optional `CliStatus.features?: CliFeatures` (images, resume, structuredOutput, permissionModes, readOnly, mcp, nativeSkills, usageReadings; filled for the built-in and custom CLIs) and `CliStatus.custom?: boolean`. New optional methods `listCustomClis?()`, `listCliTemplates?()`, `dryRunCustomCli?(descriptor, { confirmExe })` (validates; with problems nothing runs and `problems` lists them; otherwise runs version, status and one "reply OK" prompt in an empty temp folder and returns raw output beside what Harbor parsed; saves nothing), `saveCustomCli?(descriptor, { confirmExe, replace? })` (validates and rejects with every problem, records the sha256 of the executable as the approval, writes `custom-clis.json` in the data folder, re-runs discovery; `replace` updates the CLI with the same id, otherwise a used id is refused) and `removeCustomCli?(id)`. `confirmExe` must repeat `descriptor.exe`: the user's explicit OK to run that file. Behaviour that needs no further contract change: a custom CLI whose file no longer matches its approved hash is reported installed with a note and is never run (not even for its version) until saved again; routing skips it. A custom CLI with no `run.permissions['read-only']` is never given read-only work (planners, reviewers, plan mode, the concierge) unless `acceptReadOnlyRisk` is set. Custom CLIs get only a fixed allowlist of environment variables plus the descriptor's `env`. `setSettings` refuses `cliPaths` for a custom CLI. Custom CLIs are never read from a project folder.
- 0.1.30 — CLI path setting (optional). New optional `Settings.cliPaths?: Record<CliId, string>`: an absolute path to a CLI's executable chosen in Settings. Discovery uses it before the `HARBOR_<CLI>_PATH` environment variable and PATH; a configured path that is no longer a file is reported in the CLI's `note` and discovery falls back to the env var and PATH. `setSettings` merges it per CLI (`''` or `undefined` for one CLI removes that path), rejects relative paths, control characters and quotes, and rejects a path that is not an existing file; a change re-runs discovery (`cli` events follow). New optional `testCliPath?(cli, path)`: runs that CLI's version and sign-in checks against the given executable without saving it and returns the resulting `CliStatus` (rejects an unknown CLI or a path that is not an existing file). New optional `browseCliPath?()`: a file picker for an executable (`null` when cancelled). Paths are only ever taken from Settings, never from a project folder.
- 0.1.29 — Plain routing summary (optional). New optional `Message.details.summary?: string`: the routing choice in a few plain sentences for a person (which model, how hard the task looked, how much quota the CLI has, what came second). `reason` keeps the technical text, now one bullet per line.
- 0.1.28 — Delegation sizing and coordination (all optional). New optional `Agent.estimatedMinutes?: number`: Harbor's estimate of a helper's wall minutes at delegation (a prior blended with calibration). Behaviour changes that need no contract change: an edit task estimated over 25 minutes, claiming more than 10 paths, or a catch-all ("consolidate", "finish validation") is refused with a notice to the lead; each delegation turn posts a system message with the plan's estimated wall time and per-task estimates. Helper runs have a soft limit (35 min; an active run continues) and a hard limit (70 min) instead of a flat 45-minute stop, and a capped helper is resumed once automatically before the lead is woken; a helper stopped by Harbor (not by the user) now wakes the lead. A helper's question (`question` event) about files, scope or branches goes to the lead first; only credentials, destructive actions and publishing go straight to the user, and an unanswered helper question gets a safe default (always "no") after 10 minutes. An edit helper whose files overlap uncommitted edits in the project folder is held with a notice to the lead. A reviewer without `dependsOn` is bound to the single candidate when there is one. Harbor schedules one reviewer itself for an implementer whose routing said `needsReview`. Helpers running at once follow the quota budget (at most 3; 1 when a running helper's pool is in protect; none while every pool is exhausted). New lead protocol line `HARBOR_REPLY`.
- 0.1.27 — Budget routing (all optional). New optional method `setConversationDeadline?(conversationId, deadline | null)`: `deadline` is an epoch-ms time the owner needs the conversation's work by (`null` clears it); it returns the updated conversation and emits a `conversation` event. New optional `Conversation.deadline?: number`. Routing turns a deadline into urgency from the estimated minutes of the conversation's unfinished helpers (summed: a conservative critical path); without a deadline urgency is 0. Urgency shrinks the quota reserve helpers leave for interactive work and prices time, so a near deadline allows stronger or faster options. `Message.details` may carry `difficulty?: number` (0-10, computed by Harbor from the task's signals; the lead's rating is only a hint), `needsReview?: boolean` and `reviewReason?: string` (the chosen model only just clears, or does not clear, the capability floor of high work). Behaviour changes that need no contract change: the router picks model AND effort as the cheapest option that clears a capability floor computed from the difficulty, priced from the quota pools' state (scarcity, use-it-or-lose-it credit, failure risk, the cost of an automatic review); the weekly-pacing spend-up/conserve tier shifts and the low-headroom tier shift are gone, and `Message.details.scored[].headroom` is no longer filled (each entry may instead carry `effort` and `price`). `degraded` now means nothing that clears the floor was available. `lowAllowancePolicy` absent means price routing (a session moves only for a large price gap); explicit `'reduceEffort'` and `'switch'` keep their meaning. The reason text shows the calculation: difficulty and its signals, the estimated price of the choice against the runner-up, every pool's state, the reserve and the urgency.
- 0.1.26 — Steering. `send(conversationId, text, attachments?, opts?)` takes optional `opts.steer`. When true and the conversation's lead is mid-turn, Harbor aborts that turn (its native session, helpers and files are kept; no stop is recorded), tells the lead on its next turn that it was cut off, and starts a new turn from this message instead of queueing it behind the running one. Messages of turns already chained behind the running one are dropped (their reports stay held and ride along). A system message `Interrupted to follow your new message.` shows in the conversation. Without `steer`, or when the lead is idle, nothing changes. Ignored for helper conversations.
- 0.1.25 — Open in terminal, editor or Explorer. New optional `openWorkspace?(projectId, action, opts?)` with `action` `terminal` | `editor` | `folder` and `opts` `{ agentId?, file? }`: opens the project folder, or an edit helper's own worktree when `agentId` is given (it must belong to the project and have a worktree), and for `editor` and `folder` optionally one file given relative to that folder (absolute paths, `..` escapes and missing files are refused). A terminal opens in Windows Terminal, falling back to PowerShell; folder and file paths are passed as arguments or a working directory, never spliced into a command. The editor opens through its URL protocol (no shell). New optional `Settings.editor?: EditorId` (`code` default, `code-insiders`, `cursor`, `windsurf`; `setSettings` rejects other values). New type `EditorId`.
- 0.1.24 — Headroom routing, all optional. Each entry of `Message.details.scored` may carry `headroom` (`{ remainingPct, windows[] }`: the 5h and weekly windows, and any model-scoped ones, the model was judged on, with remaining percent, reset time, pace projection and whether the reading was reported or estimated). `lowAllowancePolicy` absent now means headroom routing (previously it behaved as `reduceEffort`); an explicit `'reduceEffort'` or `'switch'` is unchanged. The reason text of `details` also lists both windows of every CLI considered and, when the request's complexity was estimated, the signals.
- 0.1.23 — Quota efficiency, all optional. `Message.details` may carry the routing decision's `scored` (best three candidates with per-term points), `margin`, `tied`, `degraded` and `skipped` (CLIs and models that were not considered, and why). `UsageWindow.calibrated?: boolean` (estimated windows): false means the percentage is measured against Harbor's fallback budget, not one learned from the provider's own readings, so show it as approximate or unknown. `Settings.maxHelpersPerTurn?` (1-12, default 4) and `Settings.maxPlannersPerTurn?` (1-4, default 1): helpers beyond them in one lead turn are not started; the lead is told to confirm them.
- 0.1.22 — Paging, all optional. `listMessages(conversationId, opts?)` takes `{ before?: Id | number; limit?: number }`: with `limit` only the newest N messages come back (ascending); `before` (a message id, or an epoch-ms time) pages backwards from there; without options the whole conversation is returned as before. `getGitLog(projectId, opts?)` takes a new optional `skip` (commits to skip). New optional method `getGitLogPage?(projectId, opts?)` returns `{ commits, hasMore, note? }` for the same options: `hasMore` says another page exists and `note` is set when git timed out or failed, instead of an empty list that looks like "no commits". Behaviour changes that need no contract change: a helper that ends without a `HARBOR_RESULT` line now has `result` `{ outcome: 'partial', summary: 'helper ended without a result line', checks: [] }` (it used to be absent) and a reviewer's report starts with `NO VERDICT`; a missing verdict never satisfies the integration gate. The project's `.harbor/checks.json` runs only after the user approved its commands (a `permission` request of kind `tool` with `tool: 'Harbor checks'` and `alwaysAllow: false`; the approval is remembered per project for that exact set of commands).
- 0.1.21 — New optional method `exportDiagnostics?(): Promise<string>`: a redacted plain-text bundle for bug reports (app version, platform, CLI versions and auth states, counts of projects/conversations/agents, the tail of the run journal, the tail of the main-process log, and store startup notices such as a quarantined corrupt `state.json`). It contains no message text, prompts or file contents, and secret-looking strings are removed. The main process also rejects malformed arguments to `send`, `answerQuestion`, `setAgentPriority`, `integrateBranches` and `addProject` before the service runs (wrong type, empty or oversized ids/text, non-integer priority); `addProject(path)` now also refuses drive roots, the user's home folder itself, missing paths and non-directories with a readable error. No existing member changed.
- 0.1.20 — New `listPendingPermissions()`: the `permission` requests (tool, conflict, free reset) that still wait for an answer, with the same fields as the event, oldest first. A renderer that reloads (or opens late) calls it once after subscribing, because events are not replayed. New exported type `PendingPermission`. Pending requests are still in memory only: after an app restart the waiting agents are stopped or re-ask on their own.
- 0.1.19 — Tool permission prompts. Edit runs (the lead and edit helpers in `default`/`goal` mode; not `auto`, `plan`, the concierge or read-only helpers) now raise a `permission` event with `kind: 'tool'` when the CLI asks to run a tool outside its allowlist (Claude only; Codex has no host approval channel). New optional fields on that event: `conversationId` (the asking agent's conversation, where a system message also shows the request), `tool` (tool name), `alwaysAllow` (true when "always allow for this project" may be offered) and `expiresAt` (ms epoch; an unanswered request is denied then, default 5 minutes, and the agent is told). `answerPermission(requestId, allow, opts?)` takes a new optional `opts.always`: with `allow` true on a request whose `alwaysAllow` is true, Harbor also stores a project rule; otherwise it is a plain allow once. Answers to expired or unknown requests are ignored, as before. Stopping the agent or the conversation, or the run ending, denies its pending requests. Git merge/rebase/cherry-pick/reset/push/clean, recursive or forced deletes, network tools and URLs, publishing, privilege/process control and inline interpreter code are never always-allowed (and never matched by a rule), and neither are Write/Edit/MultiEdit/NotebookEdit/WebFetch/WebSearch. New type `ToolRule` (`{ id, tool, prefix?, created }`: a Bash command prefix of one or two whole words, or an exact non-Bash tool name), stored per project and kept across restarts. New `listToolRules(projectId)` and `removeToolRule(projectId, ruleId)` (returns the remaining rules; an unknown rule id is a no-op; both reject an unknown project).
- 0.1.18 — Rollback, write half. New `rollbackTask(agentId, target?)` queues a rollback agent and returns it: like an integrator, `role: 'other'` run by Harbor itself (`cli: 'harbor'`, `model: 'git'`), started by the user (not reported to the lead), with its own conversation `rollback: <title>`. It rejects unknown agents, the lead, a rollback agent, a blank target, and a second rollback while one in the project is unfinished. Optional `Agent.rollback?: Rollback` (`{ taskId, target?, base?, branch?, head?, merges: RollbackRevert[], conflicts?, applied? }`; `RollbackRevert` = `{ commit, agentId?, integrationId?, state: 'pending'|'reverted'|'conflict', revert? }`) marks it. A run first re-runs `previewRollback` as a gate: any blocker fails it before any git write, with `summary` `Refused: ...`. Otherwise it pins `base` (the target's head) and the task's merges, creates a new `harbor/rollback-<task>-<id6>` worktree from `base`, and reverts the merges newest first with `git revert -m 1` (each `revert` is the commit made). On a conflict the unmerged paths go to `conflicts`, the revert is aborted and the run fails with `Rollback conflict: ...`; earlier reverts stay on the rollback branch and the target is never touched. Then the project's `.harbor/checks.json` runs on `head` (`Agent.checks`/`testedCommit`). The state is `done` only when every merge is reverted and the checks pass; otherwise `failed` with `Checks failed on rollback: ...`. A message to its conversation, or `resumeAgentSession` when stopped, runs it again on the same branch and base, skipping reverts already made. `applyIntegration(agentId)` now also applies a done rollback, with the same rules (fast-forward only; rejects when not done, the project folder has uncommitted tracked changes, the target moved since `base`, the rollback branch moved, or the target is checked out in another worktree; never pushes or forces). For both kinds, applying again once the target is at `head` is a no-op. After a rollback is applied, `outdated` turns true on the reverted task, the helpers and integrators of its merges, its dependents and their reviewers (those with a `testedCommit`). New types `Rollback`, `RollbackRevert`.
- 0.1.17 — Rollback preview (read-only half of task-scoped rollback). Optional `IntegrationSource.merge?: string`: the merge commit Harbor created for that source on the integration branch (set right after a successful merge; absent when the source was already included, except that a re-run keeps the merge an earlier run made for the same pinned commit). New `previewRollback(agentId, target?)` returning `RollbackPreview` (`{ agentId?, target?, targetHead?, supported?, merges?: RollbackMerge[], files?: GitFileChange[], laterCommits?: RollbackLaterCommit[], dependents?: RollbackDependent[], clean?: boolean|null, conflicts?: string[], blockers?: string[], notes?: string[] }`, every field optional). `target` = a local branch, default the checked-out one (a detached HEAD or missing branch gives a blocker). A task is reversed only through the merge commits that brought it onto the target: those recorded in `IntegrationSource.merge`, plus older or hand-made merges whose second parent builds on the task's base and is one of its recorded heads or in its branch; for an integrator, the merges of all its sources. Work that arrived without a merge commit (fast-forward, squash, cherry-pick) is `supported: false` with an explanation. `files` = what the reverts change; `laterCommits` = commits on the target after the task's merge touching those files (`agentId`/`agentTitle` when a Harbor helper made them); `dependents` (`{ agentId, title?, state?, reason: 'dependsOn'|'spec'|'help'|'overlap' }`); `clean` = all reverts simulated newest first with `git merge-tree` apply cleanly (`false` with `conflicts` at the first conflicting one, `null` when it could not be simulated); `blockers` = the task or a dependent is queued/working/waiting, an integration for the target is running, no merge on the target, not a git repository, no base commit. `notes` always says external effects (deploys, sent messages, pushes) are not undone. The preview changes no ref, index or working tree (it may write unreferenced git objects). Rejects for the lead agent and unknown agents. New types `RollbackPreview`, `RollbackMerge`, `RollbackLaterCommit`, `RollbackDependent`.
- 0.1.16 — Optional `Settings.keepRunningInBackground?: boolean` (absent/false = existing close behavior). When true, closing the main window hides it while agents continue working; the tray offers Open Harbor and Quit. An explicit Quit follows the existing shutdown path. `setSettings` rejects non-boolean values (except `undefined`, which resets the preference). No new methods.
- 0.1.15 — Branch integration. Optional `Agent.integration?: Integration` (`{ target?, base?, branch?, head?, sources: IntegrationSource[], conflicts?, applied? }`; `IntegrationSource` = `{ agentId, branch?, commit?, state: 'pending'|'merged'|'conflict' }`) marks an integrator: a helper with `role: 'other'` (no new role) that Harbor runs itself, with no CLI (`cli: 'harbor'`, `model: 'git'`). It gates every source before any git write (an approving reviewer whose `testedCommit` is the branch's current head and is not outdated, no reviewer asking for changes on it, an existing `harbor/*` branch), pins each source head and merges SHAs with `--no-ff` into a new `harbor/integrate-<target>-<id6>` worktree from `base` (the target's head at start), in dependency then creation order, skipping sources already contained (a re-run is idempotent). A conflict is recorded in `conflicts`, the merge is aborted and the run stops (earlier sources stay merged, later ones `pending`). Then the project's `.harbor/checks.json` runs on `head` (`Agent.checks`/`testedCommit`). State `done` only when everything merged and the checks pass; otherwise `failed` with `summary` starting `Refused:`, `Merge conflict:` or `Checks failed on integration:`. A message to the integrator's conversation, or `resumeAgentSession` when stopped, runs it again. The lead creates one with `HARBOR_DELEGATE: {"role":"integrator","sources":[refs or ids],"target"?}`. New `integrateBranches(projectId, agentIds, target?)` (user-started; returns the queued integrator, which waits for the sources and their reviewers; not reported to the lead), `applyIntegration(agentId)` (fast-forwards `target` to `head` only; rejects unless the integration is done with everything merged, the project folder has no uncommitted tracked changes, and the target is still at `base`; idempotent once applied; never pushes or forces) and `getChanges(agentId)` (committed `GitFileChange[]` of a helper branch since its base, or of an integration `base..head`; `[]` without a branch). New types `Integration`, `IntegrationSource`.
- 0.1.14 — Helper results and Harbor-run checks. Optional `Agent.result?: AgentResult` (`{ outcome: 'done'|'partial'|'blocked', summary, verdict?: 'approve'|'changes', checks: {cmd, ok}[], commit? }`): the helper's own `HARBOR_RESULT` line, replaced on every run (absent when the run printed none). `verdict` comes from reviewers; `commit` is what the run examined (a reviewer's `testedCommit`, an edit helper's branch head). Its `checks` are claims. Optional `Agent.checks?: CheckOutcome[]` (`{ cmd, ok, exitCode, timedOut?, durationMs }`): commands from the project's `.harbor/checks.json` that Harbor itself ran in an edit helper's worktree after its run (evidence). They ran on `Agent.testedCommit`, and `Agent.outdated` turns true once that branch moves. Without a checks file nothing runs and edit helpers get neither `checks` nor `testedCommit`. A reviewer's approval covers the branch's current head only when `result.verdict === 'approve'` and `outdated` is false. A reviewer's follow-up re-pins `testedCommit` to the head it then examines. New types `AgentResult`, `CheckOutcome`. No new methods.
- 0.1.13 — Image attachments, conversation modes, session complexity. `send(conversationId, text, attachments?)` takes optional images (`{ name, mime, dataBase64 }`; png/jpeg/gif/webp, max 10 MB each, 6 per message); `Message.attachments?: Attachment[]` (`{ name, mime, path? }`) holds them. New `ConversationMode` (`default|auto|plan|goal`), optional `Conversation.mode` / `Conversation.goal`, and new `setConversationMode(conversationId, mode, goal?)` (goal mode requires a goal; returns the updated conversation, also emitted as a `conversation` event). Optional `SessionActivity.complexity` and `SessionActivity.effort` show how the lead turn was routed.
- 0.1.12 — Routing settings, all optional on `Settings` (absent = the previous behaviour): `concurrencyLimit` (helpers running at once per project, 1–8; default 4), `allowedModels` (per CLI, the catalog models automatic routing may pick; absent or empty = all), `rolePreferences` (per helper role a preferred `cli` and optional `model`: a score bonus that never overrides hard limits), `effortPolicy` (`adaptive`|`conserve`|`quality`), `lowAllowancePolicy` (`reduceEffort`|`switch`), `subscriptionReserve` (0–50: percent of allowance kept free; a model at or above `100 - reserve`% used is skipped) and `projectOverrides` (map by project id of `ProjectSettings`, the same fields; a project value wins per field, per CLI and per role). New types `EffortPolicy`, `LowAllowancePolicy`, `RolePreference`, `ProjectSettings`. `setSettings` rejects unknown enum values and malformed shapes, clamps and rounds numbers, drops unknown roles and blank model names; a key set to `undefined` resets that field, and `projectOverrides: { [id]: {} }` (or `undefined` for that id) removes the project's overrides. Each project entry replaces that project's previous overrides. No new methods.
- 0.1.11 — Optional `Agent.testedCommit` (the exact commit a reviewer examined, taken when its run starts) and `Agent.outdated` (computed: the reviewed branch's head moved since `testedCommit`, so the verification no longer covers it).
- 0.1.10 — New `resumeAgentSession(agentId)`: continues a `stopped` helper in its saved native CLI session (e.g. after a Harbor restart). It tells the agent to inspect its worktree first and never repeat completed steps. Rejects for the lead agent, for agents that are not stopped, and for agents without a saved session. Show it as a "Resume" action on stopped agents. (Distinct from `resumeAgent`, which only un-pauses queued work.)
- 0.1.9 — Queue controls: new `setAgentPriority(agentId, priority)`, `pauseAgent(agentId)` and `resumeAgent(agentId)`, and optional `Agent.priority` (higher starts first; absent = 0) and `Agent.paused` (a paused queued agent does not start, and stays `queued`). Pausing never interrupts a running agent. Cancelling a queued assignment is the existing `stopAgent`. The lead agent (`role: 'main'`) has no queue position: these methods reject it.
- 0.1.8 — Read-only Git view: new `getGitOverview` (branches with ahead/behind against the detected base branch, worktrees with uncommitted counts, and the Harbor helper that owns each `harbor/*` branch), `getGitLog` (commits with parents and refs for a graph), `getGitChanges` and `getGitDiff` for a `GitTarget` (`{}` = uncommitted project folder, `{ branch }` = since its merge-base with base including a helper worktree's uncommitted work, `{ commit }` = that commit against its first parent). New types `GitBranch`, `GitWorktree`, `GitOverview`, `GitCommit`, `GitFileChange`, `GitTarget`. Only branches and commits that exist in the repository are accepted; credential files are listed with `hidden: true` and their diff is never returned.
- 0.1.7 — Optional `UsageWindow.model` (a per-model limit such as Fable or Opus; absent = account-wide) and `UsageWindow.projectedPct` (where usage lands at reset at the current pace).
- 0.1.6 — Optional conversation pin/archive/custom-title fields and persisted per-conversation `activity` (state, timing, connection, model, and current step), plus optional `reviewBase`; `conversation` events update session status independently of the shared main agent. New `updateConversation`, `searchConversations`, `stopConversation`, `getReview`, and `openProjectFolder` methods. Review snapshots are read-only current diffs, with no inferred verification claims. Optional `Settings.desktopNotifications` enables native background completion/attention notifications.

- 0.1.5 — `HarborEvent` variant `question` (`requestId`, `conversationId`, `prompt`, `options?`, `allowText?`, `agentId?`) and `answerQuestion(requestId, answer)` (new method). An agent that needs a user decision ends its turn with a question; show it as a pop-up and send the chosen option or typed text with `answerQuestion`, which delivers it as the user's next message in that conversation. Renderers must ignore unknown event types.
- 0.1.4 — `Project.image?` (a small `data:image/...` URL) and `setProjectImage(id, image|null)` (new method; `null` clears it). The image is stored with the project and survives restarts.
- 0.1.3 — `Agent.conversationId?` (optional): the main-agent conversation that created a subagent. All conversations of a project share one main agent, so `parentId` alone cannot tell which chat a subagent belongs to.
- 0.1.2 — `deleteConversation(id)` (new method; removes the conversation and its messages only). `UsageWindow.period?` (`session`|`weekly`) and `UsageWindow.source?` (`reported` = read from the provider/CLI, `estimated` = Harbor-run count). Weekly windows now appear next to the 5h one.
- 0.1.1 — `CliStatus.authState?` (optional): `signedIn`, `signedOut`, or `unknown`. `signedIn` stays false when unknown, so show "status unknown" (not "login required") when authState is `unknown` and installed.
- 0.1.0 — initial contract, identical to the spec.
